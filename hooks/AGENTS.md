# hooks/

Hook scripts executed by the Claude Code harness on session events. Each script is wired in via the `hooks` block in `../settings.json`; the script file is re-read per invocation, but the settings wiring only loads at session start, so wiring changes need a fresh session to take effect.

## Conventions

- Language by weight: bash + `jq` for short pattern checks (the PreToolUse Bash guards), Python stdlib + system `python3` when logic outgrows jq (the AGENTS.md injector). Neither uses `uv run`: hooks fire on every matching tool call and must not pay dependency-resolution latency. One deliberate exception: `lint-agent-frontmatter.py` imports `pyyaml` (present in the active pyenv `python3`) and fails open if the import ever misses.
- Wire bash hooks via `bash ~/.claude/hooks/<name>.sh` and Python via `python3 ~/.claude/hooks/<name>.py`: the explicit interpreter means the scripts never need an executable bit (`chmod` is denied by this repo's permissions anyway).
- Convenience hooks fail open (exit 0 on any internal error); security hooks fail closed. State the choice in the script docstring.
- Hooks parse stdin as JSON, never regex the raw stream. Event stdin shapes and output schemas are documented in `../skills/create-claude-hook/references/hook-events.md`.
- Per-session state goes under `~/.cache/claude-agents-md/` style cache dirs, never inside this repo.

## Scripts

- `inject-agents-md.py` - Points Claude at AGENTS.md files (Claude Code natively loads only CLAUDE.md). Root AGENTS.md at SessionStart via stdout; nested ones lazily on PostToolUse (Read|Edit|Write|NotebookEdit) via additionalContext, walking the touched file's ancestry up to cwd. It emits a read-this pointer, not the file's content: Claude reliably opens an AGENTS.md once told one is nearby, so inlining only duplicated context and risked serving a stale copy. Dedup is per session per file via path+mtime state keyed by session_id plus transcript basename (isolates subagents from the main loop); compaction clears the state so files re-surface. Test battery pattern: pipe hand-built event JSON through the script and assert stdout/exit codes.
- `enforce-verification.py` - PostToolUse(Edit|Write|NotebookEdit|Bash) + Stop + SubagentStop. Pushes the agent to verify code it changes. An edit to a source file (app-code extensions only, including .vue/.svelte/.astro/.dart/.ex/.exs; markdown/config/shell/SQL excluded so the gate is not trained around) records a pending unverified change, and runs a fast linter the project opted into (ruff with a ruff/pyproject config, biome with a biome config, resolved via the project's `node_modules/.bin` first because biome is normally a local devDependency PATH lookups miss) on just that file as advisory additionalContext. Bash-mediated code writes are tracked too, false-negative-leaning: redirection targets, and code-extension tokens in `sed -i`/`tee`/`git apply`/`patch` commands (targets inside a patch body are unknowable and not tracked). A Bash command matching a test/build/typecheck/lint runner clears the pending set only on OUTCOME: the command must have succeeded (the harness gives Bash PostToolUse no exit-code field; a failed command surfaces as a raw "Error: Exit code N" string tool_response, and per the hook-events digest PostToolUse only fires on tool success, so dict-shaped = success, string-Error/missing = no clear), must not be trivia (--version/--help/--collect-only/install/init; `npm|pnpm|yarn|bun run <script>` counts only for check-shaped script names like test/lint/typecheck/check/build/e2e/ci), and must not mask failure with `|| true` / `; true`. On Stop and SubagentStop, a non-empty pending set blocks the stop once (honoring `stop_hook_active` so it never wedges) with a reason naming the unverified files; the SubagentStop wiring gates delegated work identically, since subagent edits accrue under the subagent transcript's own state key. Before blocking, the stop handler prunes any pending file that is clean against git HEAD (committed or reverted): once a change is out of the working tree there is nothing unverified left to gate, and this stops the gate re-nagging on later no-op turns after a commit. Untracked new files stay pending (they are still unverified working-tree changes), and a non-git project keeps the whole set (fail-safe). The gate enforces that verification RAN AND PASSED, not that it proved the right thing (green-but-wrong is the completion-verifier agent's and the CLAUDE.md done-gate's job). Convenience-grade, fails open. State under `~/.cache/claude-verify/` as JSON `{"pending": [paths]}` keyed `<session_id>-<transcript_basename>`; `gate-done-declarations.py` reads that exact format import-free, so state_path/schema changes must land in both. Test battery: pipe hand-built event JSON through it and assert pending-state transitions, the Stop/SubagentStop block JSON, and exit codes.
- `gate-done-declarations.py` - PreToolUse(Bash) guard. Denies `git commit` (including the `gc` alias) and `gh pr create` while enforce-verification's pending set for this session+transcript is non-empty, listing the pending files and pointing at the project's checks: committing or opening a PR is a done-declaration, and unverified changes make it premature. Also unconditionally denies sweep-staging (`git add -A`/`--all`/`-a` and bare `git add .`) with "stage specific paths, not the whole tree", encoding the recorded user lesson about dragging unrelated working-tree changes into a commit. Reads enforce-verification's state files directly (import-free; importing a sibling would create `__pycache__` here); the on-disk JSON format is the entire coupling contract. Fails open.
- `block-interactive-cmds.sh` - PreToolUse(Bash) guard. Denies `cp`/`mv`/`rm` at a statement boundary without an `-f` flag, because macOS aliases them to the `-i` interactive variants and the agent then hangs on an unanswerable prompt. The `-f` may sit in any leading flag cluster (`rm -r -f x`, `rm --recursive -f x`), not just the first. Bypasses (`command rm`, absolute path, backslash) are allowed through. Fails open: non-matching or unparseable input exits 0.
- `block-gh-watch.sh` - PreToolUse(Bash) guard. Denies `gh run watch` / `gh run list --watch`, which poll every ~3s and can exhaust the 5000/hr GitHub API quota; the denial reason points the agent at a single `gh run view`. Fails open.
- `block-no-verify.sh` - PreToolUse(Bash) guard. Denies `git --no-verify` (and the `-n` short form in any flag cluster after `commit` or the `gc` alias, so `git commit -a -n` is caught), plus any git command setting `core.hooksPath` (which skips every hook with no `--no-verify` at all). Covers `command git ...` and the `gc` alias spellings. `git push -n` (dry-run, not no-verify) is allowed, and a `-n` inside a quoted commit message is still not matched (the flag-cluster walk stops at the first non-flag token), because a guard that blocks real commit messages trains the operator to disable it. Fails open.
- `scan-read-for-injection.py` - PostToolUse(Read|WebFetch) scanner. Inspects ingested file and web content for prompt-injection markers (override phrases, summarization-survival instructions, credential-bearing or javascript/data markdown links, invisible unicode) and emits an advisory additionalContext warning at LOW (1-2 hits) or HIGH (3+). Handles the Read tool's real PostToolUse envelope, which nests the text under `tool_response.file.content`, alongside raw-string and content-block shapes. Never blocks: a match is a signal, not a verdict, and docs and security skills legitimately carry these strings. Excludes this repo's own `_refs`, security skills, and hooks, which are saturated with example payloads (exclusion paths must track skill renames: harden-security became `skills/harden/`). Fails open. Test battery: pipe hand-built Read/WebFetch event JSON through it and assert the additionalContext and exit code.
- `block-secret-writes.py` - PreToolUse(Write|Edit|NotebookEdit|Bash) secret guard. Denies writing a recognizable credential (provider key prefixes such as `sk-`/`ghp_`, AWS `AKIA` key ids, private-key headers) into a file or a shell command; the deny reason routes to an env var or secrets manager and says rotate-do-not-relocate for a live-looking key. Only high-precision prefixed shapes are matched (generic entropy is omitted so the guard stays trusted when it fires), and placeholder tells (`EXAMPLE`, `your-api-key`, `<...>`) are skipped so `.env.example` templates pass. It deliberately fails OPEN, the one security hook here that does: the threat model is accidental leakage by the sole operator, not an adversary crafting malformed envelopes, so a parser bug must never wedge every write. The reason is in its docstring; do not "fix" it to fail closed.
- `warn-context-budget.py` - PostToolUse(Read|Bash|Grep|Glob|WebFetch|Agent|Task) hook. Nudges the agent to wrap up and offer a handoff before the context window runs out, because `autoCompactEnabled` is false in `../settings.json` so a long session can wall with no soft landing. Load-bearing constraint: hooks never receive `context_window` in their stdin (only `session_id`, `cwd`, and per-event tool fields), so the hook cannot read usage directly. The statusline is the only component the harness feeds `context_window` to, so `../statusline.sh` publishes `{remaining_percentage, timestamp}` to `~/.cache/claude-context/<session_id>.json` and this hook reads that bridge. Warns once per threshold per session (WARNING at <=25% remaining, CRITICAL at <=15%); with auto-compact off context only shrinks, so each level fires at most once. Subagent handling (corrected from an earlier wrong claim here): subagents SHARE the main loop's session_id but run their own transcript, so the bridge file (which only the main loop's statusline writes and which describes only the main loop's window) stays keyed by session_id, while the dedup sentinel is keyed session+transcript like the sibling hooks, and any transcript whose basename is not `<session_id>.jsonl` (subagents live at `.../<session_id>/subagents/agent-*.jsonl`) skips warning entirely; without both guards a subagent's tool call could consume the once-per-level sentinel and mute the main loop's warning. Prunes cache files older than 7 days, matching the sibling hooks. Matched to context-growing tools only, not all, to limit per-call overhead. Convenience-grade, fails open. State under `~/.cache/claude-context/`. Test battery: plant a bridge file and pipe hand-built PostToolUse event JSON through it, asserting the warning/critical payloads, the once-per-threshold dedup, the subagent skip, the stale-file skip, and exit 0.
- `auto-resolve-questions.py` - PreToolUse(AskUserQuestion) hook. Auto-answers a question the model asks the user when it is a single-select, carries exactly one `(recommended)` option, mentions no one-way-door signal word (`delete`, `deploy`, `migrate`, `merge`, ...), and is not a scope-contract/sign-off gate (`GATE_SIGNALS`: "scope", "sign off", "confirm", "proceed with this plan", "is this correct", ...); it denies the call with a reason naming the recommended option so the model proceeds without nagging on a cheap reversible choice. A whole call resolves only if every question in it qualifies; one risky or ambiguous question sends the entire call to the user. Lightweight adaptation of gstack's question-preference enforcement, with no per-question id markers and no door-type registry; the reversibility test is the `ONE_WAY_SIGNALS` keyword list, tuned to over-match (a false "irreversible" only costs one normal prompt). Mode via env `CLAUDE_QUESTION_HOOK_MODE`: `shadow` (default, never suppresses, logs would-resolve decisions to `~/.cache/claude-question-hook/decisions.jsonl` for review), `active` (arms it; set the env in settings.json to enable), `off`. CAUTION before arming `active`: the interrogate and spec skills gate work behind AskUserQuestion scope/sign-off questions as written; without the GATE_SIGNALS exemption the active mode would auto-answer those gates with the model's own guesses, voiding the sign-off. The exemption is a conservative substring heuristic, so keep gate questions worded with those signal terms (and keep new gate wordings in GATE_SIGNALS). Convenience-grade, fails open. Test battery: pipe hand-built AskUserQuestion event JSON through it per mode and assert the deny JSON, empty let-through stdout, the gate exemption, and exit 0.
- `lint-agent-frontmatter.py` - PostToolUse(Edit|Write) advisory lint for agent definitions (paths under an `agents/` directory ending `.md`, excluding AGENTS.md/README.md/CLAUDE.md). Claude Code silently drops an agent whose frontmatter fails to YAML-parse: no error anywhere, the agent just never registers (five agents shipped broken for a month this way). The hook re-reads the edited file, parses the frontmatter with pyyaml, and on a missing/unclosed block, a YAML error, a non-mapping, or a missing `description` emits a non-blocking additionalContext warning (same advisory mechanism as enforce-verification's lint path) telling Claude the agent will be silently dropped and to use `description: >-` for values with colons or line wraps. Fails open, including when pyyaml itself is missing from `python3`.
